# MCP gateway client wiring

Cezar agent runs reach MCP servers (GitHub first) through the Obot gateway
([../bazzite/obot/README.md](../bazzite/obot/README.md)) instead of holding
per-server credentials. The Obot vMCP endpoint is the single MCP server the
runners see; which upstream servers and tools it exposes is decided in Obot.

Last verified 2026-11-03: `initialize` and `tools/list` succeed against the
vMCP, which currently fronts the GitHub remote server (46 tools).

## Configure

Copy `env.example` to `.env` here (gitignored, owner-only permissions) and set
`OBOT_MCP_TOKEN`. Or set `OBOT_MCP_URL` / `OBOT_MCP_TOKEN` (and optionally
`OBOT_MCP_CA_CERT`) in the Cezar host environment; the host env wins. Use
`CEZ_MCP_GATEWAY_ENV_FILE` to point at a different file. With no token the
gateway is off and runners behave as before.

### Finding your connect URL

`OBOT_MCP_URL` is specific to your Obot install and vMCP
(`https://<host>:8443/mcp-connect/<vmcp-id>`). The `<vmcp-id>` is generated by
Obot, so it is not committed; every setup has its own.

1. Sign in to the Obot web UI (the same host and port, without a path).
2. Open the virtual MCP server (vMCP) that aggregates your servers and copy the
   connection URL it shows. The exact menu labels vary by Obot version; look
   for a "Connect" / connection-URL field on the server's page.
3. Put it in `.env` here (used by the Cezar runners) **and** in your user
   environment as `OBOT_MCP_URL` (used by Claude Code via `.mcp.json`, which
   does not read `.env`). The `.mcp.json` default contains a `<vmcp-id>`
   placeholder, so an unset variable fails visibly rather than silently.
4. Verify with a JSON-RPC `initialize` POST (add `--cacert <root.crt>
   --ssl-no-revoke` on Windows, see TLS below):

   ```sh
   curl -s -H "Authorization: Bearer $OBOT_MCP_TOKEN" \
     -H "Content-Type: application/json" \
     -H "Accept: application/json, text/event-stream" \
     -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-03-26","capabilities":{},"clientInfo":{"name":"check","version":"0"}}}' \
     "$OBOT_MCP_URL"
   ```

   A `200` with a `serverInfo` block means the URL and token are good.

Wrong URLs look like this: the `/mcp-servers` path is the web UI (HTML on GET,
`403` on a JSON-RPC POST), and a bad token also returns `403`.

## What each runner gets

Implemented in `cezar/packages/cezar/src/core/mcp-gateway.ts`.

| Runner | Mechanism |
| --- | --- |
| Claude | `--mcp-config` with `--strict-mcp-config` (only the gateway; user/project servers are ignored). The `Authorization` header references `${OBOT_MCP_TOKEN}` from the child env, so the token is not on the command line. |
| Codex | `config.mcp_servers.obot` on `thread/start` / `thread/resume`, with `bearer_token_env_var`. |
| Copilot (ACP) | HTTP entry in `session/new` / `session/load` `mcpServers`. |

Not yet routed: Junie, OpenCode, Cursor, Pi, and Codex/Copilot user-level MCP
servers (those runners don't have a strict mode wired). Move those servers into
Obot and remove them from the user configs to complete the migration.

## Adding servers

Register each server in Obot (the GitHub remote endpoint and its read-only
tool allow-list are described in the Obot README) and add it to the vMCP.
Clients need no change. Check the result with `tools/list`: the allow-list is
not guaranteed to be applied (the vMCP once exposed write tools such as
`create_pull_request`, `merge_pull_request` and `push_files`). Hindsight has its
own private Obot vMCP and is registered in the project `.mcp.json` as
`obot-hindsight`. The automated Cezar memory-recall/retain integration still
calls Hindsight's MCP endpoint directly; its bank-specific and approval-gated
behavior is not routed through Cezar's single-endpoint gateway yet.

## Developer sessions (Claude Code windows)

The committed `.mcp.json` registers the GitHub vMCP as `obot` and the private
Hindsight vMCP as `obot-hindsight`. Both use the same `headersHelper`
(`headers.mjs`), which reads `OBOT_MCP_TOKEN` from the gitignored
`.env` here, falling back to the main checkout's copy so git worktrees need no
duplicate secret. Claude Code strips credential-named variables from helpers,
so the token cannot come from the environment. The helper only supplies
headers: `OBOT_MCP_URL` selects GitHub and `OBOT_HINDSIGHT_MCP_URL` optionally
overrides the committed Hindsight URL. Claude Code does not read either URL
from `.env`.

- First use: accept the project-trust dialog and approve both Obot servers.
- TLS: Node does not read the Windows certificate store; without the root cert
  it fails with `UNABLE_TO_GET_ISSUER_CERT_LOCALLY`. Set `NODE_EXTRA_CA_CERTS`
  persistently, then restart VS Code / the terminal:
  `[Environment]::SetEnvironmentVariable("NODE_EXTRA_CA_CERTS","<path>\obot-caddy-root.crt","User")`
  (a settings `env` entry is reported unreliable; verify with `claude --debug`).
- Checking from a shell: `curl` on Windows needs `--ssl-no-revoke` alongside
  `--cacert`, or it reports status `000`.
- The project config routes its GitHub and Hindsight MCP connections through
  Obot. Other user-level MCP servers are separate and must be audited in each
  client's user config.
